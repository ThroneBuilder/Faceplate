# Implementation Plan: Phase 005 — Save, Share, and Export

**Branch**: `005-save-share-export` | **Date**: 2026-06-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-save-share-export/spec.md`

---

## Summary

Three capabilities added to the face-shaping step: (1) auto-save/restore of the full session to IndexedDB for returning users (30-day expiry); (2) one-click ZIP download containing a masked mosaic PNG, the original crop, a BrickLink wanted-list XML, a Studio LDR model, and a readme; (3) gallery submission that POSTs only the masked mosaic PNG to a first-party Astro API route, then redirects to the Hall of Faces gallery page. All three paths are activated by enabling the disabled sidebar buttons in `FaceShapingSection.astro`.

---

## Technical Context

**Language/Version**: TypeScript strict, Astro 4.x — same as existing codebase

**Primary Dependencies**:
- `jszip` (new) — client-side ZIP generation
- `@astrojs/node` (new) — Astro hybrid output adapter for gallery API route
- Existing: Canvas 2D API (browser), IndexedDB (browser), existing palette data

**Storage**: IndexedDB (client-side, session persistence); server-side filesystem (`public/gallery/`) for submitted gallery PNGs

**Testing**: Vitest (node env) for pure functions: `session-state.ts`, `bricklink-xml.ts`, `studio-ldr.ts`. Canvas-dependent modules and the gallery API route require browser/integration testing.

**Target Platform**: Modern browsers (same as existing); Render.com Node.js deployment for gallery API route

**Performance Goals**: ZIP download ready within 5 s (SC-002); session restore within 3 s (SC-001)

**Constraints**: No original image data transmitted to any server (FR-010); all download generation client-side; Astro hybrid mode required for gallery API route

## Constitution Check

| Gate | Principle | Result | Notes |
|---|---|---|---|
| Client-only processing | I, II | ✅ | Session save is IndexedDB (browser-only). ZIP download is fully client-side. Gallery submission transmits only the masked mosaic PNG (user-derived, user-initiated output — not original pixel data) to a first-party server. Principle I prohibits third-party transmission and background transmission of user image data; the gallery share is explicit, user-consented, and first-party. |
| Deterministic output | III | ✅ | Session serialisation, XML, and LDR generation are deterministic. PNG rendering uses explicit Canvas 2D fills (same as existing pipeline). |
| Schema extensibility | IV | ✅ | `SessionMetadata` is a new interface. `LegoColor` gains no new fields — `brickLinkColorId` and `studioColorId` already exist. `AppState` unchanged. |
| Snapshot coverage | V | ✅ | No changes to the mosaic generation pipeline. Existing snapshots unaffected. |
| Algorithmic baseline | VI | ✅ | No AI/LLM dependency. All generation is deterministic. |
| TypeScript strict | Constraints | ✅ | All new modules follow `strict: true` patterns. |

**Gallery sharing — constitution note**: Gallery sharing transmits only the masked derived output (not original pixels), is explicitly user-initiated, and targets a first-party server. The constitution's prohibition on third-party and background image transmission is not violated. The ephemeral server exception (performance fallback) does not apply here — this is permanent storage of a user-consented artifact, which is a distinct permitted case.

## Implementation Notes (for /speckit-tasks)

### New npm dependencies

```bash
pnpm add jszip
pnpm add -D @astrojs/node
```

### Palette field verification (blocking prerequisite)

Before implementing BrickLink XML and Studio LDR, inspect `src/data/lego-palette.json` to confirm `brickLinkColorId` and `studioColorId` are populated for all entries. Any colours missing these fields use fallback behaviour (omitted from XML / colour 16 in LDR) and are documented in the readme.

### Astro config

Switch `astro.config.mjs` to hybrid output and add the Node.js adapter. This enables `src/pages/api/gallery/submit.ts` to be a server-rendered API route while the main app remains client-side static.

### Session save triggers in `index.astro`

| Trigger | Debounce |
|---|---|
| After `onCropConfirmed` resolves | None |
| After `onFaceShapingStart` resolves (Confirm Mosaic) | None |
| After `onMaskCellClicked` / drag end | 1 second |

### Session restore on page load

`loadSession()` is called before `renderPhase`. If a valid (non-expired) session is found, the app reconstructs `appState` as `face-shaping` using the stored metadata, skipping all upstream steps. The stored `imageBlob` is also cached for use in `downloadResultsZip`.

### Gallery groups config

`gallery-groups.json` at the repo root contains the list of valid group slugs. The API route reads this file at request time. Admin adds groups by editing this file and redeploying.
