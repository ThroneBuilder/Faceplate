## Summary

After the user confirms a mosaic, the app immediately transitions to a two-panel "Shape your face" step. The left panel is an interactive mosaic grid where clicking a cell extends or retracts the face mask to the nearest horizontal edge for that row. The right panel shows a live composite of the masked mosaic onto `Cubby.JPEG`, centred over the white 16×16 plate. The mask is initialised to an ellipse approximating the face boundary. All rendering is client-side HTML5 Canvas 2D; no workers or API calls needed.

**Project Type**: Client-side web application (Astro 4.x static site, no server)

**Constraints**: All image data stays in the browser (Principle I). No new npm dependencies. TypeScript strict mode throughout (Principle: TypeScript strict).

### Plate calibration step (during implementation)

After hardcoding initial constants in `cubby-render.ts`, render a debug overlay:
```javascript
ctx.strokeStyle = 'red'; ctx.lineWidth = 2;
ctx.strokeRect(PLATE_X, PLATE_Y, PLATE_W, PLATE_H);
```
Adjust constants until the red rectangle aligns with the white plate boundary. Remove debug overlay before committing.

### Auto-transition from mosaic-confirmed

The spec says the face shaping step appears "immediately after Confirm Mosaic." The implementation auto-transitions: in `renderPhase`, the `mosaic-confirmed` case calls `onFaceShapingStart` and re-renders, bypassing any separate button. The result row (mosaic thumbnails) is no longer shown — the face shaping view replaces it as the terminal step.
